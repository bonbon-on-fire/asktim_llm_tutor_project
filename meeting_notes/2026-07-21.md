## Notes

### Images and attachments are expensive

- Images are the single most expensive thing a student can put in a message. They go to the model as base64 `image_url` blocks, and a screenshot costs far more input tokens than the equivalent typed text.
- This matters because we just told Solver users to send screenshots (07/16 decision) — the guidance is right for quality, but it's also the costliest path we've deliberately pushed students onto.
- Current caps: **3 attachments per message** (images + files combined) — this is the binding limit, so 3 images is the real ceiling. PNG/JPEG only, 10 MB per image; non-image files 5 MB each.
- Mitigation already in place: images are attached only to the **current** student turn. Earlier turns stay text-only in the replayed history, so one screenshot is not re-billed on every subsequent message in a long conversation.
- Non-image attachments (csv/tsv/xlsx/pdf/docx/txt) are cheap by comparison — they're extracted to plain text before being sent, capped at 15,000 characters (~4k tokens) across all files in a message. Never sent as binary.
- We do not currently estimate per-image token cost anywhere; we only see it after the fact in the provider-reported input tokens. Worth adding if we want to warn students or budget properly.

### Why RAG beats putting the full course in context

- **Cost.** Dumping a full lecture corpus into every message is roughly 125k input tokens per turn — about **17× the cost per message** vs. retrieval (measured on `cities_and_climate_change`). At Sonnet 5's $3 / 1M input, that difference compounds fast across a class of students.
- **How little we actually send.** For `supply_chain_design` the indexed corpus is 850 chunks over 168 documents (~1.38M characters of lectures). Retrieval sends at most 3 chunks / 8,000 characters per turn — on the order of **0.5% of the corpus**.
- **Quality, not just cost.** More context is not better context. Retrieval gives the model the few passages that actually match the question instead of burying them in a haystack, which is what makes the citations specific ("Week 7, Lesson 3") rather than vague.
- **Chunking.** Sentence-aware splitting, ~2,400 characters (~600 tokens) per chunk with 300 characters of overlap so a concept split across a boundary still retrieves.
- **Week scoping.** Retrieval can be capped at the student's current week — it over-fetches the full ranked list, drops future-week chunks, then takes the top-k, so a future-week hit can never displace an in-scope one. This is how we avoid spoiling material the student hasn't reached.
- **Pinned vs. retrieved.** Course description and syllabus are pinned into context every turn and deliberately excluded from the index; everything else (lectures, key concepts, practice problems, OCW pages) is retrieved.
- **Fail-closed.** If retrieval returns nothing in RAG mode, the tutor does _not_ silently fall back to full context. We'd rather it say it can't find the material than quietly spend 17×.

### Archive older courses on the sandbox

- The sandbox context switcher lists every course, including ones we're no longer using, which makes the picker noisy for anyone we hand the tool to.
- There is currently **no** archive / hide / active flag to hook into. Courses aren't database rows — they're folders under `curriculum/`, and the switcher lists every subdirectory it finds. Adding this means introducing a visibility mechanism, not flipping an existing one.

### Add a new course to share with faculty

- We want a second course in AskTIM so faculty can see it running on something other than the current one.
- Adding a course is filesystem-only today — create `curriculum/<course>/` with `course_name.txt`, `pinned/course.txt`, exercises, and optionally lectures, figures, an OCW link, and `tutor_rules.txt`. Then build and commit the RAG index so deploys don't re-embed. It's picked up automatically once the folder exists.
- Sharing itself is just handing out a sandbox embed URL — there's no faculty role, invite flow, or access control. Worth deciding whether we need one before this goes wider.
