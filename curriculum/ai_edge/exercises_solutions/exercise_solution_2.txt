WHAT THE ASSIGNMENT IS TESTING
- Task 1: one-hot encoding a variable whose effect is non-linear (strength rises
  steeply to 28 days then flattens), and doing it CONSISTENTLY between train, test, and
  the candidate mixes (the encode_age helper exists precisely so the 28-day-only
  candidates do not silently collapse to the dropped baseline age).
- Task 2: propagating a model improvement through a decision — a smaller error shrinks
  the safety buffer, which lowers the strength target, which changes which mix wins.
- Task 3: recognizing that rows are not independent (many cylinders share a recipe), so
  the split has to be done at the recipe level or the test score is flattered.

Results: 1,003 rows but only 427 distinct recipes — every recipe is cast once and
crushed at several ages, so each recipe appears ~2-3 times on average. Recipes appearing
in BOTH train and test: 0.

So Priya is right: the split was rebuilt at the recipe level and no recipe straddles it.
Why it matters (qualitatively): with 427 recipes spread over 1,003 rows, a naive row-wise
split WOULD have put the same recipe on both sides — the model would "learn" a recipe at
7 days and then be scored on the same recipe at 28, so the test would measure memorization
of recipes it has effectively seen, not genuine generalization to a mix that "has never
been in a truck" (Marcus's exact concern). Because the shared count is 0 here, the ~0.82
test R2 is an honest estimate of performance on unseen recipes, which is what lets us
stand behind the bid.
