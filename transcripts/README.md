# Transcripts

Generated tutor-student conversation transcripts for the AskTim LLM Tutor project.

## Folder Structure

Current on-disk layout. Each persona folder currently has **four**
subfolders — `{persona}_raw/` / `{persona}_claude/` (ungraded / Claude-graded,
full-lecture-context pipeline) and `{persona}_raw_rag/` / `{persona}_claude_rag/`
(ungraded / Claude-graded, RAG-context pipeline) — with **108 transcripts
each** (432 per persona type; 1296 total). The whole current corpus is a
single course, `supply_chain_design` (MIT CTL.SC2x), with `tutor_prompt=tutor_05`.
The `_raw/`/`_claude/` folders are "with-lecture-context" simulations
(`internal_testing.run_transcript`); the `_raw_rag/`/`_claude_rag/` folders are
RAG-context simulations (`internal_testing.run_transcript_rag`).

```text
transcripts/
├── chaotic/                          # Chaotic student persona
│   ├── chaotic_raw/                  # Raw (ungraded) transcripts — full-context pipeline (108)
│   ├── chaotic_claude/               # Claude-graded copies of chaotic_raw/ (108)
│   ├── chaotic_raw_rag/              # Raw transcripts — RAG-context pipeline (108)
│   └── chaotic_claude_rag/           # Claude-graded copies of chaotic_raw_rag/ (108)
├── cooperative/                      # Cooperative student persona
│   ├── cooperative_raw/              # Raw transcripts — full-context pipeline (108)
│   ├── cooperative_claude/           # Claude-graded copies of cooperative_raw/ (108)
│   ├── cooperative_raw_rag/          # Raw transcripts — RAG-context pipeline (108)
│   └── cooperative_claude_rag/       # Claude-graded copies of cooperative_raw_rag/ (108)
├── clueless/                         # Clueless student persona
│   ├── clueless_raw/                 # Raw transcripts — full-context pipeline (108)
│   ├── clueless_claude/              # Claude-graded copies of clueless_raw/ (108)
│   ├── clueless_raw_rag/             # Raw transcripts — RAG-context pipeline (108)
│   └── clueless_claude_rag/          # Claude-graded copies of clueless_raw_rag/ (108)
└── README.md
```

> The tooling is still general/multi-course and historically produced other
> suffix folders (`_gpt/`, `_mini/`, `_claude_mini/`, `_raw_tutor_05/`,
> `_claude_tutor_05/`) on demand via the judge/mini runners. None of those are
> present on disk right now — only `_raw/`, `_claude/`, `_raw_rag/`, and
> `_claude_rag/` exist. The suffix conventions below document those historical
> variants for reference.

## Subfolder Convention

Each persona folder uses a suffix pattern to indicate the generation and grading
method. Only the first four suffixes below are present on disk today; the rest are
historical variants the tooling can still produce on demand.

Currently present:

- **`{persona}_raw/`** — Ungraded transcripts generated by the standard tutor+student simulation pipeline. Source-of-truth inputs to the judge.
- **`{persona}_claude/`** — Copies of raw transcripts with a `grade` object added by the Claude judge (`eval/judge/run_judge.py`, provider=`claude`).
- **`{persona}_raw_rag/`** — Ungraded transcripts generated by the RAG-context pipeline (`internal_testing.run_transcript_rag`): the tutor's prompt carries only the exercise/practice problem, and relevant lecture chunks are retrieved per student turn instead of being baked into the system prompt.
- **`{persona}_claude_rag/`** — Copies of `{persona}_raw_rag/` transcripts with a `grade` object added by the Claude judge.

Historical variants (not currently on disk):

- **`{persona}_gpt/`** — Copies of raw transcripts graded by the GPT judge (`eval/judge/run_judge.py`, provider=`gpt`).
- **`{persona}_mini/`** — Mini-continuation transcripts: a raw transcript forked at a pivot turn, with the student side replayed from file and the tutor regenerated using a new prompt or provider. Includes a `mini_continuation` metadata object. Output stem matches the source raw transcript stem.
- **`{persona}_claude_mini/`** — Claude-graded copies of `{persona}_mini/` transcripts.
- **`{persona}_raw_tutor_05/`** — Ungraded transcripts generated using `tutor_05` as the tutor prompt (produced with `internal_testing.run_transcript --output-suffix raw_tutor_05`).
- **`{persona}_claude_tutor_05/`** — Claude-graded copies of `{persona}_raw_tutor_05/` transcripts.

## Transcript JSON Schema

Every transcript file (`transcript_NNNN.json`) follows this structure:

```json
{
  "tutor_prompt": "tutor_03",
  "student_persona": "chaotic",
  "course": "cities_and_climate_change",
  "exercise_number": "01",
  "figures": [],
  "turn_size": 10,
  "context": "Course description text...",
  "exercise": "Full exercise prompt text...",
  "turns": 10,
  "exchanges": [
    {
      "turn": 1,
      "student": "Student message...",
      "tutor": "Tutor response...",
      "pedagogical_reasoning": "Internal tutor reasoning..."
    }
  ]
}
```

Graded transcripts additionally contain a top-level `grade` object:

```json
{
  "grade": {
    "sections": {
      "1_pedagogy": { "criteria": { "1.1": { ... }, "1.2": { ... }, "1.3": { ... } }, "base": { "score": 18, "max": 20 } },
      "2_dialogue_quality": { "criteria": { "2.1": { ... }, "2.2": { ... } }, "base": { "score": 11, "max": 12 } },
      "3_communication_quality": { "criteria": { "3.1": { ... }, "3.2": { ... } }, "base": { "score": 8, "max": 8 } }
    },
    "total_base_score": 37,
    "max_base_score": 40,
    "overview": "Brief evidence-based overview.",
    "judge_reasoning": "Explicit rationale for major deductions and score.",
    "total_score": 37,
    "max_score": 40,
    "model": { "provider": "anthropic", "model": "claude-sonnet-4-6" },
    "judge_llm_calls": 1
  }
}
```

### RAG-context transcripts

Transcripts produced by the RAG-context pipeline
(`internal_testing.run_transcript_rag`, the `_raw_rag/`/`_claude_rag/` folders)
carry a few extra fields and a leaner judge payload:

- **`tutor_provider`**, **`exercise_kind`** (`"exercise"` | `"practice"`), and
  **`context_mode`** (`"rag"`) top-level markers identify the run.
- **`context`** is just the short course description (`course.txt`), and
  **`exercise`** is just the problem prompt plus the run configuration. The full
  course + syllabus + lecture dump is **no longer written** into the transcript
  (the RAG tutor never saw it; what it actually retrieved per turn lives in each
  exchange's `retrieved` field) — this keeps the judge's input lean.
- Each `exchanges[i]` additionally has **`retrieved`** — the chunks RAG pulled
  that turn, `[{source, score, chars, text}]` — and **`cost`**, a per-turn cost
  estimate `{usd, calls: {student, tutor, embedding}}`.
- A top-level **`cost_estimate`** aggregates the per-turn costs:
  `{total_usd, by_component_usd, by_model, rates_note}`.

```json
{
  "tutor_provider": "claude",
  "exercise_kind": "exercise",
  "context_mode": "rag",
  "context": "Short course description (course.txt)...",
  "exercise": "Problem prompt + run configuration...",
  "cost_estimate": {
    "total_usd": 0.2113,
    "by_component_usd": { "student": 0.0266, "tutor": 0.1847, "embedding": 0.000008 },
    "by_model": { "claude-sonnet-4-6": { "input_tokens": 204659, "output_tokens": 1679, "usd": 0.1847 } },
    "rates_note": "rates from utils.pricing"
  },
  "exchanges": [
    {
      "turn": 1,
      "student": "Student message...",
      "tutor": "Tutor response...",
      "pedagogical_reasoning": "Internal tutor reasoning...",
      "retrieved": [
        { "source": "local:lecture_1_1_the_transportation_problem", "score": 0.45, "chars": 1005, "text": "..." }
      ],
      "cost": { "usd": 0.0167, "calls": { "student": { "...": "..." }, "tutor": { "...": "..." }, "embedding": { "...": "..." } } }
    }
  ]
}
```

### Key Fields

| Field | Description |
| ----- | ----------- |
| `tutor_prompt` | Tutor system prompt version used |
| `student_persona` | Student persona identifier (e.g. `chaotic`, `cooperative`) |
| `course` | Course folder name under `curriculum/` (e.g. `cities_and_climate_change`, `mathematics_for_cs`, `meaning_of_life`, `physics_iii_vibrations_and_waves`, `intro_to_international_development_planning`) |
| `exercise_number` | Exercise identifier within the course |
| `figures` | Filenames of curriculum figures (under `curriculum/<course>/figures/`) attached to this run as multimodal input; `[]` when the exercise has none. The judge re-resolves these names to re-attach the same images at grading time. Absent on pre-June-2026 transcripts (treated as `[]`). |
| `turn_size` | Planned number of exchanges |
| `turns` | Actual number of exchanges |
| `exchanges` | Array of student-tutor exchange objects |
| `grade.total_score` | Total points awarded by the judge |
| `grade.max_score` | Maximum possible score (40 for the current `rubric_08`; 46 for the older `rubric_05`) |

## Student Personas

| Persona | Behavior |
| ------- | -------- |
| **chaotic** | Challenges boundaries, tests edge cases, requests direct answers |
| **cooperative** | Good-student baseline that stays on-task and follows guidance |
| **clueless** | Genuinely confused, needs scaffolding and patience |

There is one persona prompt per type (`chaotic`, `cooperative`, `clueless`); on-disk transcripts — including the current corpus — label each run with a `<type>_NN` form (e.g. `chaotic_01`) to distinguish trials, though all `_NN` variants of a type share the same underlying persona prompt.

## Transcript Naming

Files are named `transcript_NNN.json` where `NNN` is a sequential index. The
current corpus is zero-padded to **three digits** (`transcript_001` …
`transcript_108`). Each persona-type `_raw/` folder numbers independently from
`001`. The same index across `_raw` and `_claude` folders corresponds to the
same conversation — the graded version is a copy of the raw file with a `grade`
object appended.

> Note: older transcripts from before June 2026 used two- or four-digit padding
> (`transcript_01`, `transcript_0001`); such forms may coexist in a folder.
> Numbering is set by
> `_next_transcript_number()` in [`internal_testing/run_transcript.py`](../internal_testing/run_transcript.py).
> The `_raw_rag`/`_claude_rag` folders (generated via `internal_testing.run_transcript_rag`,
> which reuses the same numbering function) currently use two-digit-minimum
> padding instead (`transcript_01` … `transcript_108`).

## How Transcripts Are Generated

Raw transcripts are produced by the tutor-student simulation pipeline:

1. Select a tutor prompt, student persona, course, and exercise.
2. Run a multi-turn conversation (default 10 exchanges).
3. Save the transcript JSON to `{persona}/{persona}_raw/`.

The `_raw_rag/` folders are produced the same way but via
`internal_testing.run_transcript_rag`, which retrieves relevant lecture chunks
per student turn instead of baking the full lecture context into the tutor's
system prompt, and also supports practice problems in addition to graded
exercises.

## How Transcripts Are Graded

```powershell
# Grade all raw transcripts with Claude (current corpus)
python -m internal_testing.run_transcript_judge --provider claude

# GPT grading is still supported by the tooling but is not part of the
# current on-disk corpus:
python -m internal_testing.run_transcript_judge --provider gpt

# Grade the RAG-context round instead (*_raw_rag/ -> *_claude_rag/)
python -m internal_testing.run_transcript_judge --provider claude --source-suffix raw_rag
```

Both commands accept `--prompt` and `--rubric` flags. Output goes to the
respective `_claude` or `_gpt` subfolder (or `_claude_rag`/`_gpt_rag` with
`--source-suffix raw_rag`). The current corpus was graded by
`claude-sonnet-4-6` against `rubric_08` (40 points).

## Visualization

Grading charts are generated by the visualization module:

```powershell
# All 11 charts (persona-type bar/heatmap/boxplot + score histogram + per-transcript lines)
python -m visualization.run_visualization

# Same charts for the RAG-context round (reads *_claude_rag/)
python -m visualization.run_visualization --rag
```

Outputs go to `visualization/outputs/` (and `visualization/outputs/rag/` with
`--rag`). See [`visualization/README.md`](../visualization/README.md) for the
full chart list.
